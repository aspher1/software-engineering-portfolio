# Track A: concurrency and shared-state audit

Scope: source review and hermetic tests on the current working tree, 2026-09-27. No live process or run file was read for mutation. Line references below refer to the post-patch working tree.

## Shared structures

| Structure | Writers / readers | Synchronization and crash/concurrency behavior |
| --- | --- | --- |
| `self.state["positions"]` | Solana/BSC `enter` adds; manage and `close_trade` update/remove; scan guard, entry cap, manager and heartbeat read. | Commit and most manager mutations hold `self.lock` (now `RLock`). Scan `guardrails_ok` reads without it, so its decision can be stale; commit rechecks caps and kill switch. A manager retains a `pos` reference after releasing the lock; another thread can remove it. Crash before `save` loses in-memory updates; after `save` state survives, although journal may lag. |
| `trades_today`, `trades_this_hour`, `day`, realized balances, cooldown | Entry commit appends, rollover/prune rebind, close updates; scan and commit read. | Entry's cap check and both appends occur in one lock at `enter` lines 1694–1713 and `enter_bsc` lines 1833–1853. `_roll_day` and `_prune_hour_trades` now take the same RLock, closing the demonstrated lost-append race. Scan's other reads remain advisory. Day rollover intentionally clears the prior day's count; an entry that commits just before midnight belongs to the old day. |
| `state.json` / `.tmp` | `save` writes; startup reads. | `save` now takes RLock itself. A failing-first direct-call test showed it formerly completed while another thread held the state lock. It writes a temp file then `os.replace`, so readers see old or new complete JSON if the replace finishes. Crash before replace leaves old state and possibly `.tmp`; crash after replace leaves new state. There is no fsync guarantee and no transaction with `trades.jsonl`. Every source call to `save` was inspected: enter, enrichment, manage, close paths were already inside `with self.lock`; the new internal lock also protects direct callers. |
| `trades.jsonl` | Entry and close `_journal` append; replay reads. | No journal lock. Each call serializes then opens append mode and calls `write` once; Python text buffering and filesystem append semantics do not prove whole-record atomicity across threads or a crash. A crash can leave a truncated line, and journal/state can disagree. Replay now skips syntactically malformed lines and counts them. Atomic journal redesign was outside conservative scope. |
| Quote paths, `_quote_path_counts`, failed quotes | Optional capture hooks write; offline readers consume files. | Quote writer uses `_quote_paths_lock` for size/count/open/write; failed quote uses `_failed_quotes_lock` for append. Crash can leave a partial final JSONL line. Module `_research_warned` and `_research_registry` are also mutable and lack locks; impact is duplicate warnings or redundant registry reads, not entry authorization. |
| `pending_entries` | Enter/enter_bsc add and discard; entry slot checks read. | All observed accesses hold `self.lock`. In-memory only; crash clears reservations. This prevents same-mint and max-open duplicate in-flight entries. |
| `decimals_cache` | `decimals` reads and populates from RPC; entry threads call it. | No lock. Concurrent misses can duplicate RPC calls; assignment of a completed value is atomic under CPython but no cross-thread single-fetch guarantee. Failure does not cache a value. No demonstrated risk-cap bypass. |
| `_px_hist` | Manage cycle creates/appends per mint; close pops. | No dedicated lock. The normal path starts one manager per position, but concurrent close and manager access can race; history is advisory dump detection and is rebuilt after restart. A lost history window could delay dump detection. This remains unpatched without a deterministic behavioral reproducer. |
| `Rpc` | Entry/manage calls use one client; `call` mutates `_id` and endpoint `_idx`. | No client lock. Concurrent IDs/endpoints may race, though each request retains its local payload and does not match responses by a shared map. Network waits occur outside the state lock in manage price fetches. No reproducible bad trade from the client fields was demonstrated. |
| `BscWallet`, lazy `_bscswap`, FX caches | BSC entry and pricing access these; `bscswap` may initialize shared client, `sol_usd`/`bnb_usd` update cache fields. | No state lock around lazy init/cache. Concurrent initialization can duplicate client creation and FX calls. No proven entry decision change; left for a focused client audit. |
| `_gt_limiter`, `_ds_limiter` | Scanner/stale checks request shared singleton; `RateLimiter` mutates tokens, failure count and circuit data. | Limiter methods use their own `threading.Lock`; singleton creation itself has no lock and could race on first use. Network and sleep occur outside limiter lock. Circuit status is fail-soft; no measured double-init in the normal one-scanner startup. |

## Verdicts and evidence

1. **Commit-time caps: verified for two concurrent commits.** Both entry paths hold `self.lock` from `_entry_commit_ok` through append and `save`. `test_commit_check_and_append_one_slot_for_two_threads` races two threads against a one-trade cap and accepts exactly one. This proves the tested code path, not a transaction across process crashes.
2. **Unlocked prune lost append: verified before patch.** `test_unlocked_prune_can_lose_commit_append` pauses list iteration, lets a locked append complete, then observes the old prune rebind discard it (0 vs 1). RLock plus locking prune/roll makes the same test retain 1. A high-volume timing race was unnecessary once the schedule was deterministic. Day rollover is a separate boundary policy, so an old-day append cleared at midnight is expected; the test does not claim that as a bug.
3. **Stale recheck while holding state lock: verified liveness hazard by source trace, unverified production impact.** `_entry_commit_ok` calls `_stale_signal_still_strong`, which calls GT/DS network fetch with 10-second timeout and may wait on a limiter, while `enter`/`enter_bsc` hold `self.lock`. All manager state updates wait behind it. The active entry configuration disables pullback waiting, so this occurs only if screening/quotes make the signal older than 180 seconds. No latency trace from the live process was taken. Left unpatched because moving the fetch before the lock changes the time at which stale strength is judged and requires a separate behavioral proof.
4. **Deadlock/lock ordering: no cycle found in reviewed paths.** `_maybe_capture_failure` called from `_entry_commit_ok` accesses optional capture settings and the module `_failed_quotes_lock`, never `self.lock`; capture hooks do not call back into Trader. With RLock, `save`, roll and prune can be called from already locked sections. No reverse path from module locks to Trader lock was found. This is a source audit, not a formal deadlock proof.
5. **Manage price network I/O outside lock: verified.** `_manage_once` releases `self.lock` after the initial position/kill check and then calls `price_native` (around lines 1972–1984). Later state updates reacquire it.
6. **Fallback rule: verified by regression tests.** `Hunter.scan` falls back only when `_scan_gt` returns `healthy=False`, defined as `pages_ok > 0`. All-page failure and first-page `ApiThrottled` engage fallback; one successful page, even empty, suppresses it. A `data: null` response now counts as one loaded empty page.
7. **Rug checks: verified by source trace.** Source only labels the signal; Solana `enter` calls `rug_check` before quoting/commit (around line 1632) and `honeypot_check` before commit (around 1690). BSC `enter_bsc` calls the BSC swap client's `honeypot_check` before quote/commit (around 1772). Neither branches on GT versus DexScreener source. This is a code-path claim; no live entry was exercised.

## Malformed-data evidence

Focused tests first failed on NaN GT gain/liquidity, NaN DS gain, GT null page, malformed main/early pool fields, a non-object pool item, valid JSON with invalid state schema, and a bad replay line. After patches, normal GT/DS field values, finite `to_f` conversions, normal rolling counts and existing replay pairing remain unchanged in golden tests. Schema fallback logs an explicit failure and starts with empty paper state; an operator should inspect the prior state file before trusting a resumed run. This task did not start the bot.
